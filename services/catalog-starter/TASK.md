# Шаг 2. Фильтр каталога по цене

## Что нужно сделать

Ручка `GET /products` умеет отдавать весь каталог и искать по названию.
Добавь необязательный параметр `maxPrice`:

```
GET /products?maxPrice=2000
```

С ним ручка отдаёт только товары не дороже указанной цены, отсортированные
по возрастанию цены. Без параметра поведение прежнее - весь каталог.

## Где править

Три файла в `internal/product`, в каждом стоит `// TODO шаг 2`:

| файл | что там сделать |
|---|---|
| `repository.go` | метод выборки в интерфейсе `Store` и его SQL в `Repository` |
| `service.go` | сценарий чтения `CheaperThan` |
| `handler.go` | необязательный параметр и выбор сценария |

SQL здесь пишется руками - это и есть разница с ORM: `WHERE price <= $1 ORDER BY price`.
Параметр приходит строкой; в число его превращает обработчик, и мусор вроде
`maxPrice=дорого` должен получить 400 с именем поля, а не пятисотку.

## Как проверить себя

```bash
go test ./services/catalog-starter/...
```

Тест `TestCheaperThanFilter` красный - четыре проверки: фильтр отсекает лишнее,
дешёвое идёт первым, граница включается (товар ровно за `maxPrice` попадает
в выдачу), и запрос без параметра по-прежнему отдаёт весь каталог. Задание
сделано, когда он зелёный и не сломались пять тестов из `api_test.go`.

## На что посмотреть по дороге

- Деньги в `decimal.Decimal`, а не во `float64`: `2000` и `1999.99` должны
  сравниваться точно. В SQL параметр уходит строкой с приведением `::numeric`.
- Граница `<=` против `<` - в требовании написано «не дороже», это включающее
  условие. Тест на границу существует именно потому, что здесь легко ошибиться.
- В списке выборки цена читается как `price::text`, и у этой колонки на выходе то же
  имя `price`. `ORDER BY price` в PostgreSQL сначала ищет имя среди выходных колонок,
  поэтому отсортирует строки как текст: `2000.00` окажется раньше `450.00`. Тест на
  порядок ловит ровно это; сортировать надо по колонке таблицы.
- Что уходит в базу: `explain select * from products where price <= 2000 order by price`
  в `psql` покажет, что по цене индекса нет и сортировка идёт в памяти.
